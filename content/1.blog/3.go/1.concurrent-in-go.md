# 🚀 Concurrency ใน Go: ทำไมถึงสำคัญ และควรใช้อย่างไร?

หนึ่งในจุดแข็งของภาษา **Go (Golang)** คือการรองรับ **Concurrency** ได้อย่างเรียบง่ายและมีประสิทธิภาพ ผ่าน **goroutine** และ **channel** ที่ทำให้เราสามารถรันงานหลายอย่างพร้อมกันได้ โดยใช้ resource น้อยกว่าการสร้าง thread แบบภาษาอื่น ๆ  

บทความนี้จะเล่าถึง use case ที่เหมาะสมในการใช้ **concurrent programming ใน Go**, ข้อดีข้อเสีย รวมถึงโค้ดตัวอย่างที่นำไปใช้ได้จริง

## 🧩 Concurrency คืออะไร?
**Concurrency** ไม่ใช่ parallelism เสมอไป แต่คือการทำให้งาน **หลายอย่างสามารถดำเนินไปพร้อมกันได้** โดยไม่ต้องรอให้งานหนึ่งเสร็จก่อนเสมอไป  

ใน Go เราสามารถเริ่มงานใหม่ได้ง่ายมาก เพียงแค่เขียน:
```go
go someFunction()
```
เท่านี้ก็ได้ goroutine ที่ทำงานแยกออกไปแล้ว 🚀

## 🔑 Use Cases ที่นิยมใช้ Concurrency ใน Go

1. ทำงาน I/O หลายอย่างพร้อมกัน
เหมาะกับงานที่ต้อง รอ I/O เช่น:
- ดึงข้อมูลจาก API หลายตัว
- อ่านไฟล์หลายไฟล์
- Query database หลาย record

ถ้าทำแบบ sequential จะต้องรอ request แรกเสร็จก่อนถึงค่อยทำตัวถัดไป แต่ถ้าใช้ goroutine → สามารถยิงพร้อมกันได้
```go
urls := []string{"https://api.a.com", "https://api.b.com", "https://api.c.com"}
var wg sync.WaitGroup

for _, u := range urls {
    wg.Add(1)
    go func(url string) {
        defer wg.Done()
        resp, _ := http.Get(url)
        fmt.Println("Got response from:", url, resp.StatusCode)
    }(u)
}

wg.Wait()
```

2. Worker Pool (จำกัดจำนวน concurrent jobs)
เวลาเรามีงานเยอะ เช่น ประมวลผลรูปภาพ 1,000 รูป หรือ query DB หลายร้อยครั้ง
ถ้าให้ทุกงานรันพร้อมกัน อาจทำให้เครื่องหรือ DB ล่ม

วิธีแก้คือใช้ semaphore หรือ worker pool เพื่อจำกัด concurrent jobs
```go
var wg sync.WaitGroup
sem := make(chan struct{}, 10) // จำกัด concurrent = 10

for i := 0; i < 100; i++ {
    wg.Add(1)
    sem <- struct{}{} // จอง slot
    go func(jobID int) {
        defer wg.Done()
        defer func() { <-sem }() // คืน slot
        fmt.Println("Processing job", jobID)
        time.Sleep(time.Second)
    }(i)
}

wg.Wait()
```

3. Pipeline / Stream Processing
ใช้ goroutine + channel ส่งงานต่อเป็น สายพาน เหมาะกับงาน data processing เช่น:
อ่านไฟล์ → parse → transform → save

```go
func generator(nums ...int) <-chan int {
    out := make(chan int)
    go func() {
        for _, n := range nums {
            out <- n
        }
        close(out)
    }()
    return out
}

func square(in <-chan int) <-chan int {
    out := make(chan int)
    go func() {
        for n := range in {
            out <- n * n
        }
        close(out)
    }()
    return out
}

func main() {
    for n := range square(generator(1, 2, 3, 4)) {
        fmt.Println(n)
    }
}
```

✅ ข้อดีของการใช้ Concurrency ใน Go
1. เพิ่มความเร็วโดยรวม (throughput สูงขึ้น)
โดยเฉพาะงานที่เป็น I/O bound (รอ DB, API, Network)
2. ใช้ resource คุ้มค่า
Goroutine เบามาก (stack เริ่มต้นแค่ ~2KB) ต่างจาก thread ที่กิน memory เยอะ
3. เขียนง่าย
go func() {} + channel ทำให้ concurrency ใน Go ดูตรงไปตรงมา
4. เหมาะกับระบบ distributed และ scalable service
เช่น web server ที่ต้องรองรับ request จำนวนมาก

⚠️ ข้อเสีย / จุดที่ต้องระวัง
1. Race condition
ถ้าหลาย goroutine เขียน/อ่านตัวแปรเดียวกันพร้อมกันโดยไม่ sync → เกิด bug ที่เจอยาก
👉 ควรใช้ sync.Mutex หรือ channel แทนการแชร์ state
2. Deadlock
ใช้ channel รอส่ง/รอรับผิดพลาด → โปรแกรมค้างได้
3. Resource overload
ถ้า spawn goroutine จำนวนมากเกินไป (เช่น 1 ล้านตัว) อาจทำให้ memory, DB connection, CPU พัง
👉 ต้องมี bounded concurrency (จำกัดจำนวน concurrent)
4. Complexity
Logic ซับซ้อนขึ้นเมื่อมีหลาย goroutine ต้องคุมการสื่อสารและการ sync ให้ดีๆ

## 🎯 สรุป
- Concurrency ใน Go เหมาะกับงาน I/O bound, high throughput, และงานที่สามารถรันขนานกันได้

- ควรใช้ร่วมกับ WaitGroup, channel, semaphore, worker pool เพื่อควบคุม flow และป้องกัน overload

- ถ้าใช้ถูกที่ถูกทาง จะได้ performance ที่ดีขึ้นมาก แต่ถ้าใช้ผิด อาจทำให้ system ช้าลงหรือล่มได้

## 💡 ท้ายสุด:
*ใช้ concurrency เพื่อ “ซ้อนเวลา” ของงานที่ต้องรอ I/O หรือ resource — แต่ไม่ใช่ทุกงานที่ทำ concurrent แล้วจะเร็วขึ้น*
