# 🚀 ยกระดับ GitHub Copilot ให้ฉลาดขึ้นด้วย Awesome Copilot

Copilot ปกติช่วยเขียนโค้ดได้ดีอยู่แล้ว แต่ถ้าคุณอยากให้มัน "เข้าใจโปรเจกต์ของคุณจริง ๆ" — เข้าใจโครงสร้าง, สไตล์, เฟรมเวิร์ก, และแนวคิดเฉพาะของทีม — คุณต้องสอนมันผ่าน **Awesome Copilot Architecture**

แนวทางนี้ใช้ไฟล์และโฟลเดอร์พิเศษ 5 ส่วน ได้แก่ `scripts`, `chatmodes`, `agents`, `instructions`, และ `prompt` ซึ่งเมื่อรวมกันแล้วจะเปลี่ยน Copilot ให้กลายเป็น "AI Developer ที่เข้าใจโปรเจกต์ของคุณจริง ๆ"

## 🧭 ภาพรวมแนวคิด

โครงสร้าง Awesome Copilot คือการ "ห่อหุ้มบริบท (context)" ให้กับ Copilot แทนที่คุณจะต้องอธิบายทุกครั้งว่า "ให้เขียน Go API แบบ clean architecture" คุณสามารถเก็บคำสั่งและกฎทั้งหมดไว้ใน repo ให้ Copilot อ่านอัตโนมัติ

```
my-project/
├── scripts/
├── chatmodes/
├── agents/
├── instructions/
└── prompt/
```

## 🧠 1. instructions — สมองของ Copilot

> "สอน Copilot ให้เข้าใจโครงสร้างและมาตรฐานของโปรเจกต์คุณ"

โฟลเดอร์นี้คือจุดเริ่มต้นของทุกอย่าง ในนี้จะมีไฟล์ `.md` ที่อธิบายว่าโปรเจกต์เขียนยังไง ใช้เฟรมเวิร์กไหน มีแนวปฏิบัติอะไรบ้าง

```markdown
# instructions/go-api.md

This project is a Go REST API using Gin + GORM.
Follow clean architecture: handler → service → repository.

Guidelines:
- Use context.Context in all methods
- Return JSON responses
- Write unit tests with testify
- Use zap for logging
```

💡 **ประโยชน์จริง**: Copilot จะอ่านไฟล์นี้ทุกครั้งที่ช่วยเขียนโค้ด → มันจะรู้เองว่าคุณต้องการโครงสร้างแบบไหน โดยไม่ต้องอธิบายซ้ำ

## 🪄 2. prompt — คำสั่งต้นแบบ (Reusable AI Prompts)

> "คือ template ของสิ่งที่คุณอยากให้ Copilot ทำซ้ำ ๆ"

เช่น สร้าง CRUD, เขียน test, ทำ refactor, หรือสร้าง Swagger docs คุณสามารถเก็บเป็น prompt แบบ reusable ได้เลย

```markdown
# prompt/create-crud.md

Generate a CRUD API for the resource {ResourceName} using Gin and GORM.

Include:
- handler, service, and repository layers
- validation with go-playground/validator
- unit test example using testify
```

แล้วเรียกใช้งานด้วย command เช่น:

```bash
copilot run --prompt ./prompt/create-crud.md --var ResourceName=User
```

💡 **ประโยชน์จริง**: ไม่ต้องเริ่มเขียน CRUD ใหม่ทุกครั้ง — Copilot จะสร้างโครงพร้อมเทสให้ครบ

## ⚙️ 3. scripts — automation layer ของ AI

> "ใช้สคริปต์เชื่อม Copilot เข้ากับ workflow จริงในโปรเจกต์"

ใน repo อาจมีสคริปต์ bash หรือ Node.js ที่ใช้รัน Copilot พร้อม prompt ที่ตั้งไว้

```bash
# scripts/new-api.sh
#!/bin/bash
RESOURCE=$1
echo "Generating new API for $RESOURCE..."
copilot run --prompt ./prompt/create-crud.md --var ResourceName=$RESOURCE
```

จากนั้นแค่รัน:

```bash
bash scripts/new-api.sh Product
```

💡 **ประโยชน์จริง**: คลิกเดียว Copilot จะ generate ไฟล์ `/internal/api/product_handler.go`, `service/product_service.go`, และ `repository/product_repo.go` ให้ครบ!

## 💬 4. chatmodes — สร้าง "โหมดบุคลิก" ของ Copilot Chat

> "ให้ Copilot คุยกับคุณใน persona เฉพาะ เช่น Go Expert, DB Optimizer, หรือ API Reviewer"

```yaml
# chatmodes/go-expert.yaml
name: Go Expert Assistant
persona: Senior Go Developer
context_files:
  - instructions/go-api.md
goals:
  - Write idiomatic Go code
  - Explain design decisions
  - Suggest clean architecture patterns
```

เปิด Copilot Chat แล้วสั่ง:

```
"Switch to chat mode: Go Expert Assistant"
```

ตอนนี้ Copilot จะตอบคุณเหมือนนักพัฒนา Go ระดับ Senior ที่เข้าใจโปรเจกต์คุณทุกซอกทุกมุม 🧑‍💻

💡 **ประโยชน์จริง**: ช่วย mentor ทีม, review โค้ด, หรืออธิบาย design decision ได้แบบเจาะจง

## 🤖 5. agents — AI ตัวช่วยเฉพาะทาง

> "เหมือนมี Copilot ตัวพิเศษคอยทำงานด้านเดียว เช่น เขียนเทสหรือ refactor โค้ด"

```yaml
# agents/test-writer.yaml
name: GoTestAgent
role: Write unit tests for Go services
context_files:
  - instructions/go-testing.md
prompt: |
  Write table-driven tests for {FunctionName} using testify and httptest.
```

เรียกใช้งานใน Copilot Chat:

```
"@GoTestAgent write tests for service/user_service.go"
```

Copilot จะ generate unit tests พร้อม mock, context, และ test table ให้ครบ ✅

💡 **ประโยชน์จริง**: ลดเวลาการเขียน test, เพิ่ม coverage, และได้ pattern ที่สม่ำเสมอ

## 🧩 ทำไมแนวทางนี้ถึง Powerful

| ด้าน | ผลลัพธ์ |
|------|---------|
| 🎯 Context Awareness | Copilot เข้าใจสไตล์และสถาปัตยกรรมของโปรเจกต์จริง |
| ⚡ Speed | แค่รัน script หรือ prompt ก็ได้โค้ดพร้อมใช้งาน |
| 🧱 Consistency | ทุก module ใหม่มีโครงสร้างเหมือนกันหมด |
| 🧪 Automation | Agents เขียน test และ docs ให้ได้เอง |
| 💬 Smart Collaboration | Chatmodes ทำให้ Copilot พูดภาษาทีมคุณได้จริง ๆ |
## 🚀 การปรับใช้กับโปรเจกต์จริง

ตัวอย่างโฟลเดอร์ในโปรเจกต์ Go API:

```
my-go-api/
├── internal/
│   ├── api/
│   ├── service/
│   ├── repository/
│   └── model/
├── docs/
│   └── ai/
│       ├── instructions/
│       ├── prompt/
│       ├── chatmodes/
│       └── agents/
├── scripts/
│   └── new-api.sh
└── .github/
    └── copilot-instructions.md
```

### Workflow การใช้งานจริง

1. เขียน `instructions/go-api.md` อธิบาย pattern ของโปรเจกต์
2. สร้าง `prompt/create-crud.md` สำหรับ CRUD generator
3. เขียน `scripts/new-api.sh` เพื่อเรียก Copilot ด้วย prompt
4. เพิ่ม `chatmodes/go-expert.yaml` เพื่อให้ Copilot เข้าใจ context ตอนคุย
5. ใช้ `@GoTestAgent` เขียนเทสให้อัตโนมัติ

## 🧩 บทสรุป

**Copilot ที่ฉลาด** ไม่ใช่แค่ "ช่วยเขียนโค้ด" แต่ **"เข้าใจโปรเจกต์ของคุณเหมือนทีมจริง ๆ"**

ด้วย **Awesome Copilot architecture** — คุณสามารถทำให้ Copilot เป็น:

- **Code generator** ที่รู้โครงสร้างทีม
- **Mentor** ที่ตอบตามแนวคิด clean code
- **QA bot** ที่ช่วยสร้างเทส
- และ **Dev assistant** ที่อยู่ใน workflow จริง

### 💡 Tip ปิดท้าย

คุณสามารถเริ่มต้นง่าย ๆ ด้วย:

```bash
mkdir -p docs/ai/{instructions,prompt,agents,chatmodes}
mkdir scripts
touch .github/copilot-instructions.md
```

แล้วเพิ่มเนื้อหาทีละส่วนตามที่อธิบายด้านบน — แค่นี้ Copilot ของคุณก็จะเริ่ม **"เข้าใจ"** โปรเจกต์อย่างลึกซึ้งขึ้นในทุกบรรทัดของโค้ด 💥
