# Git flow คืออะไร?

**Git flow** คือ คือการแยก Branch ออกมาเพื่อพัฒนา Feature เพื่อแยกส่วนการทำงานให้ชัดเจนหรือการจัดการ Sourch Code ให้ง่ายต่อการจัดการและทำให้การพัฒนาโปรเจคของ Developer ไปในทิศทางเดียวกันและช่วยลดปัญหาที่จะเกิดขึ้นระหว่างการทำงานร่วมกัน

## มาทำความรู้จัก Branch ใน Git flow กันเถอะ :sunglasses:

โดยหลักๆ จะมี Branch หลักอยู่แค่ 2 Branch เท่านั้นในการพัฒนาก็คือ main หรือ master และ develop ส่วนที่เหลืออีก 3 Branch จะใช้สำหรับ พัฒนา/ตรวจสอบ/แก้ไข ได้แก่ Feature Branch, Release Branch และ Hotfixes Branch นั่นเอง โดยจะอธิบายรายละเอียดย่อยแยกเป็นแต่ละหัวข้อให้ฟังแบบให้เข้าใจ Concept คร่าวๆของ Git flow ลุยกันโล้ดดด :yum::partying_face:

### Master Branch or Main Branch
- เป็น Sourch Code ที่พร้อมใช้งานหรือพร้อมที่จะ deploy เสมอเพื่อ Release ไปให้ลูกค้าใช้งานจริงบน Production
- ส่วนมากจะไม่ทำการพัฒนาบน Branch Master แต่จะแตก Hotfixes บน Branch นี้เป็นการแก้ไขบัคเร่งด่วนที่อาจจะส่งผลกระทบ Critical บน Production
- ต้องติด tags version

### Develop Branch
- เป็น Branch ที่ใช้พัฒนาเป็นหลักส่วนมาก Develop เมื่อพัฒนา Feature ของตนเองเสร็จแล้วจะขอ merge มายัง Branch นี้
- ใช้สำหรับแก้ไข bug เพราะ Branch จะเป็นแหล่งรวมของ Feature Develop ทำให้อาจจะเกิดบัคได้มากมายจะทดสอบและแก้บัคก่อนที่จะโยนให้ QA ทดสอบเสมอ
- พัฒนาโดยการแตก Branch Feature ออกมาใหม่ทุกครั้ง

### Feature Branch
- เป็น Branch ที่ถูกสร้างมาจาก Develop Branch
- เป็น Branch ที่สร้างขึ้นมาเพื่อพัฒนา Feature อะไรสักอย่างและเมื่อเสร็จก็จะทำการ me​rge request ไปยัง Develop Branch และจะถูกลบไป

### Release Branch
- เป็น Branch ที่ถูกสร้างมาจาก Develop Branch
- เป็น Branch สำหรับ QA หรือ Tester เพื่อทำการทดสอบก่อนที่จะ Release ไปยัง Production
- เมื่อเทสเสร็จและเกิดปัญหาก็จะโยนไปให้กับ Develop เพื่อทำการแก้ไขจนเทสผ่านทั้งหมดก่อนที่จะปล่อยไปใน master branch

### Hotfixes Branch
- จะเป็น Branch ที่แตกมาจาก master branch
- เมื่อทำการ Release ไปแล้วและเกิดบัคขึ้นต้องแตก branch นี้มาทำการแก้ปัญหาโดยเร่งด่วน
- เมื่อแก้ไขเสร็จจะทำการ merge ไปยัง develop branch และ master branch

## สรุป
Git flow นั้นเป็น Concept หนึ่งที่คิดค้นขึ้นมาเพื่อแก้ไขปัญหาการพัฒนาเป็นทีมลดความขัดแย้งและปัญหาที่ซ้ำซ้อนที่อาจจะเกิดขึ้นภายใน sourch code และง่ายต่อการพัฒนาและทำการ on Production ได้อย่างสบายและช่วยคัดกรองปัญหาบน Production ได้มาก ซึ่ง Git flow นั้นก็เป็นแค่ขั้นตอนหรือวิธีการอีกแบบหนึ่งในการจัดการ โดยจะเหมาะสมกับทีมคุณหรือไม่ควรนำไปปรับใช้กันอีกที โดยอาจจะนำ Concept ของ Git Flow นี้ไปปรับปรุงก็ได้เพื่อให้ทีมได้ใช้ง่ายขึ้นและลดปัญหาของการที่ Developer จะต้องทำการเรียนรู้ Concept ของ Git Flow ใหม่ (สำหรับคนที่ไม่รู้ว่า Git flow ใช้ยังไงทำไปทำไม) Blog ต่อไปต้องลองมาใช้ Git flow ในการใช้งานกันจริงเถอะดูว่าจะยากอย่างที่คิดไหม ติดตามได้ใน Blog ถัดไปเลยครับ :point_right: :point_right: [Basic command Git flow](https://www.devpai.netlify.app/blog/blog/git/basic-command-gitflow)
